# appsettings.json

KitsuneCommand's server-side config lives at `<UserDataFolder>/KitsuneCommand/appsettings.json`: the 7D2D user-data folder (the one that holds `Saves/`), not inside any one save, so it survives new worlds. On Windows that's usually `%APPDATA%\7DaysToDie\KitsuneCommand\`, or wherever `serverconfig.xml`'s `UserDataFolder` points. It's a small JSON file that's generated on first launch if missing.

## Default file

```json
{
  "WebUrl": "http://*:8888",
  "WebPanelPort": 8890,
  "WebSocketPort": 8889,
  "DatabasePath": "KitsuneCommand.db",
  "AccessTokenExpireMinutes": 1440,
  "RefreshTokenExpireDays": 7,
  "ServerSettingsFileName": "serverconfig.xml",
  "EnableCors": false,
  "CorsOrigins": "http://localhost:5173"
}
```

## Settings

| Key | Default | Description |
|-----|---------|-------------|
| `WebUrl` | `http://*:8888` | Internal API bind address. The panel listener forwards API calls to this URL's port, so you can move it. You still open the panel on `WebPanelPort`, not this port. |
| `WebPanelPort` | `8890` | Frontend/login port: the one you open in your browser or point a reverse proxy at. |
| `WebSocketPort` | `8889` | WebSocket server port for real-time events (console log stream, map updates, chat). |
| `DatabasePath` | `KitsuneCommand.db` | SQLite database file path, relative to `<UserDataFolder>/KitsuneCommand/`. |
| `AccessTokenExpireMinutes` | `1440` | Access token lifetime in minutes (default 24 hours). |
| `RefreshTokenExpireDays` | `7` | Refresh token lifetime in days. |
| `ServerSettingsFileName` | `serverconfig.xml` | Name of the `serverconfig.xml` file that the Config Editor reads and writes. |
| `EnableCors` | `false` | Turn on for frontend dev (Vite on `localhost:5173`). Leave off in production. |
| `CorsOrigins` | `http://localhost:5173` | Allowed origin when `EnableCors` is `true`. |

## Changing ports

The panel uses three ports: the API (`WebUrl`), the panel itself (`WebPanelPort`) and live updates (`WebSocketPort`). Each must be different from the other two and free on the host. To run two servers with KitsuneCommand on one machine, give the second one its own set, for example:

```json
{
  "WebUrl": "http://*:9888",
  "WebPanelPort": 9890,
  "WebSocketPort": 9889
}
```

Then restart that server and open the panel on `http://your-server-ip:9890`. The page picks up the WebSocket port from the server, so there's nothing to change in the browser.

If you use a reverse proxy or tunnel, point the panel route at `WebPanelPort` and the `/kctunnel` route at `WebSocketPort` (see [Troubleshooting](../troubleshooting/index.mdx) for the Cloudflare Tunnel specifics).

:::caution[KitsuneCommand 2.10.1 and earlier]
Older builds ignore `WebPanelPort` and always listen on 8890, and they always forward API calls to port 8888 whatever `WebUrl` says. On those builds, leave all three ports at their defaults.
:::

## Security notes

- Tokens are signed server-side. Rotate the secret (regenerated on first run) by deleting `KitsuneCommand.db`. But be aware this also wipes users, points, and purchase history, so only do it on a fresh install.
- `EnableCors: true` should only be used for local development. It widens the API surface to cross-origin callers.
- The web panel port (8890) should be firewalled if the server is on the public internet and you only want authorized admins reaching it. Put it behind a VPN or a reverse proxy with HTTP auth for extra defense in depth.

## Applying changes

Most settings in `appsettings.json` are read on startup. After editing:

1. Stop the dedicated server.
2. Save the file.
3. Restart the server.

Changes to ports or CORS definitely require a restart. Token lifetime changes apply to *new* tokens issued after the restart; existing tokens continue using their original lifetime.
